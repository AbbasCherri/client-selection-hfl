# Single source of truth for the Python environment — exact-pinned, covers
# the full dependency closure (direct + transitive). Consolidates what used
# to be a floor-pinned requirements.txt (for installability) plus a separate
# requirements-lock.txt (exact pip-freeze snapshot); this file now plays
# both roles; pyproject.toml's own `dependencies` stay floor-pinned (>=) so
# `pip install .` without this file still resolves to something workable.
#
# Verified against the environment the full sanity-check suite
# (tests/sanity_checks/run_all.py, 13 scripts / 72 checks) passes against,
# Python 3.13.14. Dev/editor tooling (ruff, black, mypy) is intentionally
# NOT here — installed separately via `pip install -e ".[dev]"` per
# scripts/gcp_setup.sh. pytest and its exclusive deps (iniconfig, pluggy)
# are also intentionally excluded: this project's checks are the plain
# scripts under tests/sanity_checks/, not pytest (see that directory's
# _lib.py header) — pytest was a leftover from before that switch.
#
# Regenerate: pip freeze --exclude-editable, then re-apply the exclusions
# above (grep this file's git history for the exact exclude list) — do NOT
# just paste a fresh `pip freeze` wholesale, it will reintroduce dev/test
# tooling and, in a contaminated environment, unrelated stray packages.
#
# PyTorch is a CPU build (`+cpu` local version suffix). That suffix is ONLY
# published on the CPU wheel index, never on PyPI — a plain `pip install
# torch==2.12.1+cpu` with no other index configured fails with "No matching
# distribution found" (confirmed: PyPI lists 2.12.1 but not 2.12.1+cpu). The
# --extra-index-url below makes this file self-sufficient for a single `pip
# install -r requirements.txt`; scripts/gcp_setup.sh additionally
# pre-installs torch/torchvision from that same index before this file so
# the generic dependency resolution pass has less work to do, but that step
# is now a (harmless) optimization, not a correctness requirement.
--extra-index-url https://download.pytorch.org/whl/cpu
